### P1-L 시험 모듈

Android의 프레임 코덱과 등록 클라이언트는 독립 빌드 가능한 `:session` 라이브러리에 둔다. 같은 Kotlin 코드를 로컬 JVM 시험에서 실행해 Windows의 실제 TLS 상대와 연결할 수 있다. 시험 상대는 매번 생성한 인증서를 자식 프로세스 파이프로 전달하고 루프백에만 바인딩한다.

**D-08 채택 · 등록과 폐기.** 등록 전 TLS에서도 클라이언트 인증서로 개인키 소유를 확인한다. 등록 전용 포트를 두어 승인 대기 상태에서 일반 세션 처리기에 접근할 경로를 없앴다. 신뢰 단위는 공개키 지문이며 같은 키로 인증서를 갱신할 수 있다. Windows 호스트는 사용자 전용 디렉터리에 지문만 저장하며 한 프로세스가 목록과 활성 연결을 소유한다. Android는 앱 전용 Keystore의 P-256 키와 승인된 PC 지문을 사용한다. 실기기 시험에서 키 선택·Wi-Fi 권한 흐름을 확인하고, 두 포트가 방화벽 또는 배포에 부담이 되면 TLS 프로토콜 협상으로 포트를 통합하는 방식을 재검토한다. [Android Keystore](https://developer.android.com/privacy-and-security/keystore)

**D-09 채택 · 버전 및 순번 검사.** Windows와 Android 세션 API가 Hello/Welcome을 교환하고 송신 시 ID와 방향별 순번을 붙인다. 수신 시에는 본문을 할당하기 전에 헤더의 ID와 순번을 검사해 이전 연결의 데이터가 처리기에 도달하는 것을 막는다. Android의 협상 본문은 기존 시험에 사용하던 Gson 2.11.0의 엄격한 JSON 모드로 읽어 JVM과 Android에서 같은 구현을 사용한다. 두 번째 프로토콜 버전을 도입할 때 공통 버전 선택과 협상 후 헤더 형식의 호환성을 다시 시험한다.

**D-10 채택 · P1 복구와 기기 호환.** Android 16의 실제 Conscrypt는 TLS 서명용 다이제스트를 계산한 뒤 Keystore에 서명을 위임했다. SHA-256만 허용한 초기 키에서 `INCOMPATIBLE_DIGEST`를 관찰해 P-256 키에 사전 계산 다이제스트 서명을 허용했다. Windows는 현재 사용자 CNG 키를 비내보내기로 유지하고 인증서를 열 때 같은 SPKI 지문을 재사용한다. 일반 포트에서 인증 거부가 소켓 종료로만 보이는 경우에는 별도 등록 포트의 ALPN 상태 조회로 자기 키의 폐기를 판별한다. 플랫폼 TLS 구현이나 등록 포트 정책이 바뀌면 실기기에서 세 경로를 함께 재시험한다.

**D-11 채택 · 혼잡 및 권한.** Android 큐를 세션별 프레임 수와 바이트 수로 제한하고, 포화 때 신뢰 데이터의 재시도와 미리보기 생략을 구분한다. 1초 Ping, 3초 감시, 0.5초부터 최대 8초까지 지터를 둔 백오프를 사용한다. 다음 부하 시험에서 필기량·무선 절전·스냅샷 크기에 맞춰 한도를 재검토한다. target 37 앱은 Android 17에서 직접 TCP 연결 전 런타임 권한을 확인하며 거부 후 복구 경로를 제공한다. [Android 로컬 네트워크 권한](https://developer.android.com/privacy-and-security/local-network-permission)

## 다음 결정에 필요한 증거

**D-12 채택 · P2 대상과 수명.** PC가 선택한 모니터의 전체 물리 크기를 Digitizer ACK에 포함한다. 태블릿이 같은 비율의 입력면과 세 점 보정을 직접 표시하고, 호스트는 0부터 1까지의 좌표만 선택 모니터에 매핑한다. 연결마다 주입 장치를 지연 생성하고 종료·모드 전환 때 폐기한다. 새 모니터로 자동 대체하면 사용자가 선택하지 않은 앱에 입력될 수 있어 대상 식별자와 배치가 달라지면 세션을 종료한다. 디스플레이 구성이나 복제 모드를 동적으로 지원할 때 대상 식별과 보정 수명을 재검토한다.

**D-13 채택 · Canvas 동기화.** Android가 1024×640 sRGB 문서를 소유하고 임시 레이어의 획을 UP에서만 합친다. 해시는 무손실 RGBA 원본으로 계산한다. 확정 ACK가 하나 밀리면 다음 획을 계속 로컬에 반영하고, 기준 revision이 건너뛰면 최신 전체본을 보낸다. 스냅샷 한 장은 2,621,440바이트다. 공유기 부하에서 전체 복구 시간이 문제가 되거나 문서 해상도를 올릴 때 압축과 다중 사각 영역을 다시 검토한다.

1. S9 FE+의 OS/One UI 버전별 호버·버튼·기울기 방향표와 압력 분포. 배럴 버튼이 특정 설정에서만 들어오면 조건을 기능표에 남긴다.
2. 진단 수신기와 대상 드로잉 앱의 호환성표. 필압 대체를 마우스 클릭으로 자동 전환하면 펜으로 판정할 수 없으므로 실패 원인을 먼저 분류한다.
3. 중간 밝기 반투명 브러시와 모서리 획에서 확정 픽셀 해시, 전체/델타 바이트 수, 재동기화 시간. Android와 Windows가 각자 획을 다시 그리는 방식만으로는 픽셀 동등성을 보장하기 어렵다.
4. 제품 지연 예산, 최대 캔버스 크기, 페어링 UX 및 USB 배포 방식. [프로토콜](PROTOCOL.md)에 명시한 한도는 첫 부하 시험의 시작값이다.

**D-14 채택 · Windows 배포와 오버레이.** 사용자별 WiX MSI에 x64 .NET 및 Windows App SDK를 동봉한다. 개발 환경에 있던 런타임과 빌드 경로에 의존하지 않도록 게시 단계에서 컴파일된 XBF와 앱 PRI도 함께 수집한다. Windows Installer가 설치·주 버전 업데이트·제거를 처리하고, 사용자 설정과 CNG 키는 설치 대상 밖에 둔다. 배포 크기 또는 조직의 코드 서명·Store 배포 요구가 바뀌면 MSIX와 공유 런타임 방식을 재검토한다. 두 번째 Win2D 창은 기존 복제본을 읽고, 본창에서 layered/transparent 창 스타일을 복원할 수 있다. [자체 포함 배포](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/self-contained-deploy/deploy-self-contained-apps) · [Windows 계층 창의 입력 판정](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)

**D-15 채택 · 직접 배포와 첫 등록.** 직접 배포는 자체 포함 x64 MSIX와 동일한 릴리스 키로 업데이트하는 APK로 구성한다. PC는 기존 TLS 등록에 필요한 PC 주소·전체 지문·일회용 비밀을 QR로 표시하고, 태블릿은 앱 안에서 이를 읽은 뒤 사용자에게 대상 PC를 확인받는다. PC에서 태블릿 지문을 승인하는 절차와 초대 만료 시간은 기존 등록과 같다. PC는 QRCoder, Android는 ZXing Embedded와 AndroidX 카메라 권한 확인 및 Activity 결과 처리를 사용한다. 카메라 사용이 불가능하면 같은 값을 직접 입력한다. 기존 시험 MSI의 배포 형식은 D-14에 기록했다. 외부 배포 전에는 수신 PC가 발급자를 신뢰하는지, 인증서 변경 후 기존 패키지가 업데이트되는지 확인한다.

**D-16 채택 · 태블릿 벡터 원본과 Windows 보관함.** 태블릿은 페이지 UUID와 버전, 브러시, 색, 굵기, 필압 설정, 경로별 압력 표본을 내부 파일에 원자적으로 저장한다. 부분 지우개 경로도 벡터로 보존하여 확대 표시와 SVG 내보내기에 같은 지운 영역을 적용한다. Windows에는 태블릿이 렌더링한 확정 PNG와 순서가 있는 목록을 저장한다. 앱의 인증 세션이 열리면 모드 선택 전에도 보관함을 복구할 수 있도록 선택 기능 `pages-v1`을 추가했다. 요청한 페이지가 모두 도착하면 기기별 목록 파일을 교체한다. 기존 실시간 미리보기와 디지타이저 주입에는 각 모드의 승인이 계속 필요하다. Windows에서 벡터 편집이나 고해상도 재출력이 필요해지면 원본 전송 형식을 재검토한다.

**D-17 채택 · Windows 벡터 표시와 SVG 내보내기.** PC에서 PNG를 확대할 때 생기는 흐림을 줄이기 위해 보관함의 기존 인증·배치 전송에 INK1을 추가한다. Android의 필압 표본과 브러시 속성을 같은 페이지 버전의 PNG와 함께 저장하고, PC는 현재 배율로 획 윤곽을 채운다. 부분 지우개는 SVG 마스크로 보존한다. 이전 앱의 PNG 보관함도 읽을 수 있도록 벡터 지원 여부와 페이지 치수를 목록에 기록한다. 대용량 페이지에서 전체 벡터의 재전송이나 도형 생성 시간이 필기 지연을 유발하면 획별 증분 전송을 재검토한다.

**D-18 채택 · 페이지 제목 동기화.** 제목 변경만으로 PNG와 INK1을 다시 보낼 필요가 없도록 페이지 목록에 선택 필드 `titles`를 추가한다. 그림과 제목은 같은 목록 배치에서 확정한다. 이전 앱은 필드가 없거나 추가되어도 기존 순번을 표시할 수 있다. 제목을 여러 기기에서 편집하게 되면 메타데이터 버전과 충돌 처리 방식을 재검토한다.

**D-19 채택 · 페이지별 캔버스와 탐색 권한.** 기존 필기 UUID와 파일을 유지하고 태블릿의 페이지별 순서 목록으로 캔버스를 묶는다. 연결된 두 Windows 창은 같은 선택과 확정 그림을 공유한다. Windows의 탐색 요청은 인증 세션 안에서 태블릿이 확정하며 오프라인 요청을 다음 세션으로 넘기지 않는다. 캔버스 생성과 삭제는 태블릿에서 수행한다. 여러 쓰기 기기를 동시에 지원하게 되면 탐색과 문서 구조의 충돌 처리 규칙을 재검토한다.

**D-20 채택 · 캔버스 전송량 절감(CV-02, NET-01).** 대각선 획과 지우기에서 넓은 빈 영역을 반복해서 보내는 비용을 줄이기 위해, 마지막으로 확인된 Android 픽셀과 비교해 단일 사각형 또는 32×32 변경 타일을 선택한다. 양쪽 런타임이 제공하는 zlib로 큰 본문을 무손실 압축하고, PC는 복원 후 전체 해시를 확인한다. 보관함은 짧은 연속 편집을 묶어 최신 PNG와 필압 원본을 함께 보낸다. 해상도별 전송 바이트, 펜을 뗀 뒤 ACK까지의 지연, 보관함 반영 시간을 측정해 타일 크기·압축 기준·묶음 간격을 재검토한다.

**D-21 채택 · 캔버스 브러시 질감(CV-02).** 태블릿과 PC가 같은 질감 타일을 사용하고, 질감이 있는 페이지만 INK2로 전송한다. 화면 확대와 SVG 내보내기에서도 같은 종이 결을 그리면서 기존 페이지 캐시와 INK1 호환성을 유지하기 위한 선택이다. 캔버스의 기존 색과 섞이는 물감이나 획 방향을 따라 움직이는 붓결이 필요하면 고정 타일 방식과 벡터 형식을 재검토한다.

**D-22 채택 · Wi-Fi Direct(NET-02).** Windows가 자율 그룹 소유자로 무선 그룹을 열고 LegacySettings로 클라이언트 접속을 받는다. Android는 WifiNetworkSpecifier로 해당 그룹에 가입한다. 주변 PC 검색 후 PBC 초대가 실패한 기기 조합에서 코드 방식으로 연결과 재접속이 확인되어 제품의 Wi-Fi Direct 경로를 하나로 통합했다. 대기를 시작할 때마다 임의의 WPA2 연결 코드를 생성하며, 태블릿은 이를 직접 입력하거나 Windows 화면의 연결 QR을 스캔한다. Windows는 피어의 로컬 IPv4 주소에서만 등록과 세션을 받고 Android는 해당 Network에 소켓을 바인딩한다. 무선 그룹 가입 후 처음 등록하는 기기는 별도의 등록 QR과 지문 확인을 거친다. IPv4를 제공하지 않는 환경을 지원해야 하면 주소 선택을 재검토한다.

**D-23 채택 · 초대 QR의 포트 전달.** 사용자가 포트를 변경한 PC에도 스캔 한 번으로 등록하고 세션을 열 수 있도록 호스트가 현재 대기 중인 두 포트를 초대에 담는다. 기존 초대와 호환되도록 필드 생략 시 종전 기본값을 사용한다. 호스트가 실행 중 대기 포트를 바꿀 수 있게 되면 이미 발급한 초대의 유효 조건을 재검토한다.

**D-24 채택 · 캔버스 표시와 보관함 동기화(CV-02).** Windows는 단일 메인 창을 복원하고 오버레이는 독립적으로 표시한다. 캔버스가 보이는 창이 있을 때만 실시간 스트림을 구독한다. 트레이에서도 태블릿이 확정한 필기를 오프라인으로 열 수 있도록 페이지 보관함은 계속 동기화한다. Android에 창 표시 여부를 전달하는 선택 기능을 추가해 숨겨진 동안의 미리보기와 중복 픽셀 전송을 줄인다. 보관함 전송 자체의 전력·대역폭 비용이 문제가 되거나 여러 PC가 독립적으로 구독하게 되면 전송 정책을 재검토한다.

## D-25 · 획 단위 변경 동기화와 SQLite 보관함 (CV-01, CV-02)

2026-11-24 확정. 0.11.0에서 획 단위 보관함을 도입하고 D-24의 트레이·오버레이 동작을 유지한다.

1. **원본과 전환.** 태블릿은 새 보관함 ID를 발급하고 빈 SQLite 보관함에서 시작한다. 기존 Android .ink는 가져오지 않는다. 같은 태블릿의 기존 PC 보관본은 새 보관함의 기준 상태를 온전히 받은 뒤 교체할 수 있다. 전송 중 끊기면 직전 보관본을 계속 열 수 있어야 한다.
2. **태블릿 커밋.** SQLite WAL과 synchronous=NORMAL을 사용한다. 한 번의 편집에 해당하는 획 변경, 문서 버전, 보관함 단위 순번과 전송할 변경 기록을 한 트랜잭션에 저장한다. 커밋 성공 후에만 확정 변경을 게시한다. 펜을 움직일 때의 미리보기는 임시 표시로 처리한다. 획 ID와 그리기 순서, 좌표·필압, 브러시·질감 속성을 보존한다. 획 전체 삭제는 ID로 전달하고, 부분 지우개는 순서가 있는 지우기 획으로 전달한다. 실행 취소·다시 실행과 페이지·캔버스의 생성·삭제·이동·이름 변경도 순번에 포함한다.
3. **Windows 보관함.** 연속된 변경을 묶어서 받고, 변경된 획·목록과 마지막으로 적용한 순번을 같은 SQLite 트랜잭션에 저장한 뒤 보관함 저장 완료를 회신한다. 실시간 화면의 픽셀 수신 확인과 구분한다. 정상 동기화는 매 묶음마다 전체 캔버스 PNG나 벡터 파일을 다시 만드는 작업을 요구하지 않는다.
4. **재연결.** PC가 저장한 보관함 ID와 마지막 순번 및 해당 이력을 식별하는 값을 제시한다. 같은 이력이면 바로 다음 순번부터 받는다. 수신 중 끊긴 묶음은 마지막 커밋 지점부터 다시 받고, 회신만 유실된 묶음은 중복 적용하지 않는다. 새 보관함이거나 이력이 갈라졌거나 필요한 기록이 정리되어 이어받을 수 없을 때만 목록을 대조한다. 페이지 구성과 캔버스별 획 ID·내용 버전·그리기 순서를 비교해 누락·변경·삭제를 반영하고, 대조 기준 순번 이후의 편집을 이어받는다.
5. **트레이와 오버레이.** 시작 메뉴에서 다시 실행하면 기존 메인 창을 복원한다. 트레이에서도 연결과 확정 변경의 보관함 동기화는 유지한다. 오버레이만 보이면 거기에만 실시간 필기를 표시한다. 캔버스를 표시하는 창이 없으면 실시간 캔버스 전송과 그리기를 멈춘다. 트레이의 종료 메뉴는 앱을 완전히 종료한다.

**표시와 내보내기의 완료 기준.** 같은 보관함·캔버스의 같은 확정 버전에서 두 장치의 화면, PNG와 SVG는 획 굵기, 그리기 순서와 반투명 겹침, 지운 영역, 브러시 질감이 시각적으로 일치해야 한다. 같은 캔버스 크기·배경·배율에서 비교하고 SVG는 같은 뷰어에서도 비교한다. PNG와 SVG의 파일 바이트 일치는 요구하지 않는다. 실시간 픽셀 전송의 CV-02 해시는 해당 경로의 무결성을 확인한다.

## D-26 · 캔버스 미리보기의 시점과 필압 전송 (CV-02)

0.11.3에서 실시간 표시, 완성된 획 우선 표시, 펜을 뗀 후 표시를 제공한다. 실시간 모드는 첫 점 이후 33ms 단위로 묶고, 완성된 획 우선 모드는 펜을 대고 1000ms가 지난 시점부터 중간 표시를 시작한다. 짧게 그은 획이 중간에 나타나지 않기를 원하는 기존 사용자를 위해 펜을 뗀 후 표시 선택을 유지한다.

Android 0.11.4에서는 완성된 획 우선 표시의 후속 주기를 500ms로 정했다. 첫 1000ms 이후에도 미완성 획을 띄우는 횟수를 줄이고, 펜을 떼면 다음 주기를 기다리지 않고 확정한다.

Android 0.11.6에서는 짧은 획의 표시 동작이 같은 두 선택을 완성된 획 우선 표시로 통합했다. 긴 획은 첫 1000ms 이후 250ms마다 새 입력을 보내고 펜을 떼면 즉시 확정한다. 지우개는 두 모드 모두 확정 결과만 동기화한다.

기존 JSON 프레임을 확장하고 필압을 4096단계 정수로 보내 전송량을 점당 쉼표 포함 최대 5바이트만 추가한다(필압 필드 기준). Windows에서 확정 벡터와 같은 규칙을 재사용하여 브러시를 그린다. 실기기에서 긴 획의 프레임 지연이나 전송량 문제가 관찰되면 먼저 배치별 전송량과 렌더링 비용을 측정한 뒤 간격과 인코딩을 재검토한다. [구현 범위와 완료 기준](CANVAS_PREVIEW.md)

## D-27 · 펜을 뗀 뒤 확정된 획의 우선 표시 (CV-02)

0.11.5에서는 저장을 마친 짧은 획을 독립적으로 보내 Windows의 현재 선명한 바탕에 그린다. 태블릿 저장과 확정 픽셀 검증, 보관함의 편집 배치를 유지하면서 연속 필기 때 첫 표시가 이들을 모두 기다리는 경우를 줄이기 위한 결정이다. 추가 통신과 렌더링 비용을 제한하기 위해 진행 중에 미리보기를 보낸 획은 재전송하지 않으며, 표본·큐 한도를 넘으면 기존 화면 전송을 사용한다. 실기기에서 효과를 판단할 때는 펜을 뗀 시점부터 해당 획이 메인 창이나 오버레이에 처음 보인 시점까지 측정한다.

## D-28 · 표시 모드를 지우개에도 적용 (CV-02)

부분 지우개와 획 지우개도 필기와 같은 표시 시점을 사용한다. 실시간 표시에서는 지우는 동안 PC로 진행 상황을 보내고, 완성된 획 우선 표시에서는 첫 1000ms를 기다린 뒤 250ms 단위로 갱신한다. 두 모드 모두 펜을 떼면 남은 입력을 즉시 처리한다.

부분 지우개는 경로와 굵기를 보내고, 획 지우개는 태블릿의 삭제 판정을 사용해 바뀐 영역을 64픽셀 조각으로 다시 그려 보낸다. Windows에 원본 벡터가 아직 도착하지 않았더라도 겹친 획과 이전 지우기의 결과를 유지하기 위해서다. 미리보기는 메모리에서만 처리하고 저장과 실행 취소는 기존 지우기 한 번을 단위로 삼는다. 양쪽이 기능을 지원할 때만 사용한다. 큰 페이지의 연속 지우기에서 전송이나 다시 그리기 비용이 문제가 되면 조각 크기와 전송 방식을 재검토한다.

## D-29 · 펜 릴레이의 제품명과 연결 식별자 통합

0.11.12부터 사용자 화면에는 펜 릴레이(Pen Relay), 기술 식별자에는 `PenRelay`를 사용합니다. Android 패키지는 `dev.penrelay.app`, Windows 패키지는 `PenRelay.Desktop`입니다. 초기 제품과 분리해 설치하고 기기를 새로 등록합니다.

두 기기가 같은 제품의 연결 요청을 식별하도록 프레임의 처음 4바이트(`PRLY`), 등록 상태 확인용 TLS 식별자(`penrelay-status/1`), 두 종류의 QR 식별자와 Wi-Fi Direct 그룹 이름을 함께 변경했습니다. 초대, 승인, 상호 인증과 데이터 처리 순서는 기존 설계를 따릅니다. 다른 버전의 클라이언트와 연결해야 할 때 호환 범위와 버전 협상을 재검토합니다. [프로토콜](PROTOCOL.md)
